3 · Focus-order findings

3.1 Breaking changes / blast radius

CONFIRM Login now requires a CAPTCHA

verifyLogin adds required|captcha. This is intended, but it is a behaviour change: any automated/integration login (if any) must now solve the CAPTCHA. Session-backed, so it works with the existing UA-binding middleware. Confirm no headless client depends on this endpoint.

CLEAR Exemption chooser routing

exemptionApplication returns a different view only for the "Registered but Now Seeking Exemption" category; every other category and the save flow are unchanged. View-only.

3.2 Logic / correctness

CLEAR OTP throttle — verified

Send: 5 allowed, 6th blocked ~10 min. Verify: 5 wrong counted, 6th blocked ~10 min; a correct OTP resets the counter. Keyed by mobile number; send/verify counted separately; per-flow isolation (registration/password_change/forgot_password).

CLEAR Medical-doc validation gap fixed

Previous === 'medical' never matched "Medical Grounds", so required/type/size were skipped. Now stripos(...'medical') + SafeUploadedDocument + SingleFileExtension run. Verified: Document1.txt.pdf.pdf, scan.jpg.pdf, shell.php.pdf → BLOCK; genuine files pass.

6 · Open / conditions

Carry-over CAPTCHA image is OCR-weak

config/captcha.php: lines=0, quality=100, single colour → trivially OCR-solvable. The CAPTCHA now guards login & exemption, but for real bot resistance, harden the image (lines/noise/quality/colours, sensitive=true). One config change hardens all CAPTCHAs.

Data test category visible

fc_exemption_master.pk 6 is visible=1, so it appears in the chooser (and category page). Set visible=0 to show exactly the 3 real categories.

Ops Throttle needs a persistent cache

OTP throttling uses the cache store (same as the OTP itself). Production CACHE_DRIVER must be persistent (file/redis/database) — if OTP delivery works, throttling works.

Note Double-extension strictness

A genuine resume.doc.pdf is rejected and must be renamed — intended for the finding, recoverable by rename.

Terminology CAPTCHA ≠ MFA

The login CAPTCHA is anti-automation, not a second factor. If the audit's MFA item strictly requires MFA, an actual second factor (OTP/TOTP) is still needed — report the CAPTCHA as "brute-force/anti-automation," not "MFA".
