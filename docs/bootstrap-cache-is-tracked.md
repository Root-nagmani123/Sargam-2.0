# `bootstrap/cache/` is tracked on purpose — do not revert it as "generated noise"

`bootstrap/cache/packages.php` and `bootstrap/cache/services.php` are generated by
`php artisan package:discover`. In most Laravel projects they are gitignored. **In this
repository they are committed**, and reverting them because they look like build output
has broken the application more than once.

## Why it matters

These files list the service providers Laravel instantiates at boot. If they name a
provider whose class is not present in `vendor/`, **every route returns 500** — the
application cannot boot at all.

That is not hypothetical. At commit `449657052` (`main`), both files named:

| Provider | Present in `vendor/`? |
| --- | --- |
| `Livewire\LivewireServiceProvider` | No — not in `composer.json` either |
| `Yajra\DataTables\ExportServiceProvider` | No — required in `composer.json`, not installed |

Verified with:

```bash
git show 449657052:bootstrap/cache/services.php | grep -c LivewireServiceProvider   # 2
php -r "require 'vendor/autoload.php'; var_dump(class_exists('Livewire\\LivewireServiceProvider'));"  # false
ls vendor/yajra/    # buttons, fractal, html, oracle — no export
```

PR #311 regenerated both files, which removed those two entries. **That change is a boot
repair, not incidental churn.** It is the fourth consecutive PR to move these two files,
and each time the diff has looked like noise a reviewer might drop.

## Rules

1. **Never revert a `bootstrap/cache/*.php` change without re-running the app.** If a
   revert looks harmless, load any route before believing it.
2. **Run `php artisan package:discover` after deploy**, so the committed manifest matches
   the vendor tree actually deployed.
3. **If you add or remove a Composer package, regenerate these files in the same commit**
   and say so in the PR description. A dependency change that leaves them stale is the
   exact failure above.

## The real fix, when someone has time

Untrack them and let `package:discover` own them:

```bash
git rm --cached bootstrap/cache/packages.php bootstrap/cache/services.php
echo 'bootstrap/cache/*.php' >> .gitignore
```

This is **not** done here because it only works if every deployment path runs
`package:discover`. Confirm that first — a deploy that just pulls code would ship with no
manifest at all.

## Known outstanding inconsistency

`composer.json` requires `yajra/laravel-datatables-export ^1.2`, but it is not in
`vendor/`. The declared and installed dependency sets disagree. Resolve deliberately —
**not** with a bare `composer install`, because `vendor/` is ahead of `composer.lock` in
this repository and a plain install would downgrade a large number of packages.
